# amuzesh Audit Report — 2026-11-09, 0.3.0

**Scope:** the P(-1) pass the release rules require before a minor cut, over what 0.3.0
changes: the `[lib]` manifest section, `dist/`, the new raw-include test and
`scripts/consumer-check.sh`, the CI and release workflows, and the consumer
documentation. The model code is unchanged since the full sweep
([`2026-11-09-audit.md`](2026-11-09-audit.md)), apart from one `include` line.
**Baseline:** 0.2.2 (commit `5492456`, cyrius 6.7.18). **Result:** 0.3.0.

## Summary

Three low findings, all fixed. distlib could not see the bundle's own allocator need, and
wrote a bundle with no `# Requires` block and no sidecar. CI's actions still sat on the
majors the 0.2.2 audit noted. A release of a library published no library artifact.
Nothing reaches the model code or the validation contract.

## Method

- **Toolchain sweeps (6.7.18):** fmt `--check`, lint and doc on every `src/` and `tests/`
  file; `cyrius vet`; `cyrius deps --verify`; `cyrius distlib --check`. All clean.
- **A real consumer:**
  - a project scaffolded by `cyrius init` (6.7.18), declaring `[deps.ganita]` and
    `[deps.tyche]` by git tag and `[deps.amuzesh]` by path;
  - resolved with `cyrius deps`, then built and run against the bundle: fit, classify,
    converge;
  - repeated with the three declarations in reverse order, which gave the identical binary.
- **`scripts/consumer-check.sh`:** the raw include built with `--no-deps` (5/5), the whole
  unit suite rebuilt against the bundle (123/123, every bit-exact known answer), and the
  fuzz harness rebuilt against the bundle (0 violations).
- **Gate mutation.** A `src/` edit left un-regenerated makes `cyrius distlib --check` exit 1
  (`STALE`). A bundle without `src/data.cyr` makes the consumer check exit 1.
- **Workflows.** Every `ci.yml` step was run locally from the parsed YAML, and the release
  packaging commands were dry-run. The action SHAs were checked against the upstream tags
  with `git ls-remote`.
- **Benchmarks** re-stamped with `scripts/bench-history.sh`: every row is within noise of
  0.2.2 (−1.4% to −5.3%, no kernel changed).

## Findings

### LOW — fixed

| # | Finding | Where | Fix |
|---|---|---|---|
| 1 | **The bundle shipped with no `# Requires` block and no `.deps` sidecar**, so `include "dist/amuzesh.cyr"` did not name the allocator it calls. amuzesh's sources include nothing; the manifest auto-prepends. The distlib verify then never saw `alloc` / `ALLOC_MAX` undefined, because ganita's bundle brings `alloc`, so it credited the leaf to the named dep. cyrius's guide says a bundle's own call into such a leaf is recorded; at 6.7.18 it was not ("0 derived by the verify"). | `src/check.cyr` | `src/check.cyr`, the module that calls the allocator, includes `lib/alloc.cyr`, with a comment saying why. distlib starts the sidecar from kept includes, so `dist/amuzesh.deps` lists `alloc` and the bundle opens with its `# Requires` block. |
| 2 | **CI ran actions on older majors** (checkout v4, gh-release v2), carried over from the 0.2.2 audit's observations. | `.github/workflows/` | checkout v7.0.1 `3d3c42e5…`, gh-release v3.0.3 `efb35369…`: the commits the tags resolve to on 2026-11-09, identical to tyche's pins. gh-release v3 takes the same three inputs. |
| 3 | **A release published no library artifact**: a tarball and the demo binary, nothing a consumer imports. | `release.yml` | The release runs `cyrius distlib --check` and ships the committed `dist/amuzesh.cyr` and `.deps` as checksummed assets. It checks rather than regenerates, so the asset is byte-identical to what `cyrius deps` fetches from the tag. |

## Observations — not changed, and why

- **The raw-include test cannot catch a missing `alloc` declaration**, because ganita's
  bundle brings `alloc` too. It does catch any other leaf the bundle needs but does not
  declare, which is what it is for.
- **A consumer declares ganita and tyche itself.** Named deps are not sidecar leaves; only
  stdlib leaves are. This is the same arrangement as rosnet's tyche dependency, and the
  docs give the three-dep manifest. Declaration order does not matter (verified both ways).
- **The manifest keeps `[build] test` and the test leaves in `[deps] stdlib`.** The
  6.7.18 template writes `[test] files` and `[test] stdlib = ["assert", "bench"]`, which
  keeps those leaves out of production builds. But `[test] stdlib` is not prepended to a
  plain `cyrius build`, and CI builds the suite that way: the aarch64 leg and the consumer
  check. So the move would also need explicit includes in the suite. tyche keeps the older
  spelling for the same reason. Worth doing as its own change, not inside a packaging
  release.
- **`src/data.cyr`, the `amz_make_blobs` fixture, ships in the bundle.** Whether it stays
  public API is the 0.5.x freeze review's call.
- **distlib regenerates and checks sidecars on x86-64 Linux only** (cyrius guide). CI's
  runner is one.
